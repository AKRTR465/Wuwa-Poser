# 游戏兼容定义与动态发现

## 维护入口

`data/game_compat/ww_runtime.json` 是默认桌面播放器的游戏兼容常量维护源。它包含原生地址、字段与容器布局、函数长度、托管绑定名称及业务状态值。角色骨架、Morph 和原生物理组签名仍由各角色 profile 管理。

修改维护源后运行：

```powershell
./tools/generate_game_compat.ps1
./tools/generate_game_compat.ps1 -Check
```

生成器输出两个文件，不要手工编辑生成物：

- `runtime/generated/GameCompat.generated.h`：`native` 与 `shared` 条目，供全部 C++ 模块编译。
- `runtime/generated/GameCompat.generated.cs`：`managed` 与 `shared` 条目，桌面程序和游戏内托管桥链接编译同一份文件。

三个分区共用一个命名空间，名称不得重复；每个条目具有 `type` 和 `value`。支持 `u32`、`u64`、`i32`、`string`、`wstr`，以及从无符号条目派生文本 RVA 的 `hexref`（`@常量名`）。只有一端使用的常量放进 `native` 或 `managed`。

生成物携带配置标识和源文件摘要。此摘要用于发现本工程各 DLL、托管代码与观察器之间的配置混用；它不代表游戏内存 ABI 已验证。构建会生成定义，校验和离线 CI 会拒绝过期生成物。改配置后需要重新编译相关模块；直接改变游戏 API 签名或原生结构语义仍需要修改适配代码。

原生入口会在取得演员之前与实际已加载的托管助手握手。Mono 保留的旧助手缺少握手方法、或者其编译来源不同，都会拒绝开始；需要重启游戏以加载新助手。普通打包也要求当前 schema 2 manifest，旧运行时需要重建。

## 已接入的动态发现

正式播放初始化时先对配置的 GObjects/名字池地址进行结构和名称交叉验证。若验证失败，则使用现有只读扫描器搜索主映像可读写区域，要求恰好一组互相一致的候选，再次验证后使用。扫描不会写游戏或调用待识别函数。

解析后的实际 RVA 会写入各演员的 `native_target.json`，继续传给身份登记和原生图观察器。序列号分配器使用的对象数组基址由实际 GObjects 地址及已知结构关系计算，不再退回默认全局地址。

每演员的实例地址、converter/group 节点相对位置和 compact 骨骼映射仍从本次会话获得。跨进程对象指针不会作为固定布局复用。扫描器仍依赖所支持的 UObject/FName 基础编码，不能自动适配任意对象结构变化。

## 原生函数验证与诊断候选

身份登记、图观察和正式原生物理准备会消费其需要的函数字节证据。在安装相关 hook 或调用相关函数之前，核对配置来源、完整字节长度、映像边界和实际代码；不再仅因存在 witness 字段就声称布局已验证。

函数字节证据保存在按版本命名的 `data/runtime_contracts/native_functions_<版本>.json`，其 `source_sha256` 必须等于 `SourceBuildSha256`；身份登记使用 `data/native_identity_registration_contract.json`。C# 按函数语义 label 提取一致的字节证据，并使用统一配置中的执行 RVA；缺失、冲突或游戏构建不符时拒绝开始。身份登记契约在会话目录中生成部署副本，原始档案不变。

字节不符时直接拒绝安装，不会在映像中另行搜索候选位置。函数位置相同也不证明 ABI 或动画阶段相同。

运行报告：

- 会话根的 `game_compatibility.json`：全局锚点来源、实际 RVA、交叉验证结果；只代表锚点验证范围。
- 身份/图观察结果的 `checks_performed`：实际执行的配置来源和代码检查。
- 各演员原生输入目录的 `native_function_checks.json`：正式原生物理函数检查与失败原因。

## 鸣潮 3.8.0 验证进度

已用 3.8.0 资源包复核全部 65 个角色配置和 82 个角色／皮肤的模型及 UI 动画类映射，并加入莉莉和绯雪「月沉霜」的骨架、表情和原生物理图签名。现有其他角色的骨架与动画图内容沿用各自的来源记录。

已比对 3.8.0 游戏程序集与旧版构建引用。托管桥的 33 项反射绑定均可解析，字段类型、静态属性和方法签名一致，托管桥使用 3.8.0 引用编译通过。

早期 3.8.0 候选在演员加载前的 GameThread 检查停止，恢复记录已确认。针对磁盘 EXE SHA-256 为 `38b3980f0436d8ead42a0ff8c45c183936ed02cd8b4b33944a03316b68cfd887` 的构建，三个带明确诊断文本的检查点一致指向登记 ID `0x9698480` 和初始化标记 `0x9698490`。游戏内读取到标记为 1，ID 与窗口线程一致，修正后已验证演员加载和恢复。会话报告在 `worker_result.game_thread_check` 记录字段读取结果。

演员加载后的只读报告交叉验证了 `GObjects` 和 `NamePool`。角色骨架资产指针位于 `0xe8`。两次诊断从角色骨骼读取函数确认了 `0x3c8`，并核对该数组全部 388 个骨名及父索引。同两次会话的骨骼网格组件在 `0xab8` 槽位指向动画发布函数 `0x4cfc880`。

随后四处指令引用一致指向帧计数 `0x9698458`，采样确认数值递增。当前 `PlayerCameraManager` 的镜头槽位与 `0x51d6560` 的函数签名匹配。表情目标数组在 `0x378`，其中的 `MorphTarget` 名单和角色配置一致。表情函数候选位于 `0x4d13810`，其代码引用的组件权重表仍在 `0xef0`。

莉莉的 367 骨索引和父索引已在游戏内核对。骨架校验按 ASCII 字母忽略骨名显示大小写，保留骨骼顺序、父索引及数字后缀检查。关闭原生物理的实机测试已完成播放和恢复，记录 581 帧，启用了表情和 VMD 镜头。开启原生物理时，四个旧版动画入口未通过字节校验，观察器在安装前退出，游戏恢复已确认。

3.8.0 原生物理的三个虚表由磁盘映像的槽位关系与函数展开记录定位。只读实机诊断核对了 18 个槽位，并采集姿势转换、Kawaii、缓存姿势计数及对象身份登记所需的 14 个函数的完整字节。构建按当前游戏映像摘要选择 `data/runtime_contracts/native_functions_3_8.json`，安装前校验全段字节。求值指令确认骨架、网格、帧号和计数器的代理字段偏移已变更。

身份登记核对回调实例、网格和骨架指针。图观察对关联动画实例核对网格归属，并重验同一会话中主动画实例提供的代理。绯雪「月沉霜」的配置按实机网格骨骼顺序重排，逐骨核对了原资产的父骨关系与姿势映射。

实机 CLI 完成莉莉、绯雪「月沉霜」各一场单人测试，以及一场 6 秒双人测试。双人会话中，每位演员收到 157 帧原生输入，分别观察到 13 组和 11 组物理节点生效，停止后恢复检查通过。

物理编辑器的 3.8.0 只读诊断补充采集了 `GroupUpdatePhysicsSettings`（`0xa5d990`）和 `GroupSimulate`（`0xa5b750`）。`GroupEvaluate` 在缓存尚未初始化或 `node+0x160` 的逐次刷新标记开启时调用参数更新函数。组内阻尼、回正强度和摆角上限分别位于 `node+0x108`、`node+0x114`、`node+0x11c`，更新函数将它们写入逐骨缓存的 `+0x28`、`+0x34`、`+0x3c`，并在有曲线时叠加曲线值。模拟骨数组始于 `node+0x1f8`，元素间距为 `0x1b0`。

设置 `WWPOSER_OBSERVE_KAWAII_SETTINGS=1` 后，图观察器比对这两个函数的完整字节，再在 `native_graph_discovery.json` 中记录选中实例的组参数、缓存头尾样本和刷新标记。2026-11-15 的莉莉会话按根骨匹配了全部 13 组，裙摆组 12 的原值为 0.2、0.2、50°。观察窗口内自然求值的 Float 组 7 同时读到了逐骨缓存。随后原生播放记录 130 帧并通过停止恢复。该次会话没有覆盖调参写入及写入后恢复。

同日的调参试验把莉莉裙摆组 12 的阻尼、回正强度和摆角上限设为 0.05、0.11 和 65°。该组有 10 根模拟骨，求值后读到的缓存首尾均为新值。只还原阻尼后，读回 0.2、0.11 和 65°。其他组的请求仍是原厂值，停播恢复检查通过。调参前验证 `GroupEvaluate`、`GroupUpdatePhysicsSettings` 和 `GroupSimulate` 的完整代码。每次求值后还原节点参数，并调用原生更新函数重建原厂逐骨缓存。

莫特斐左袖骨链 `Piao_L_xiuZiA01` 的参考根骨挂在 `Bip001LForearm` 下。原生播放的骨姿输入在袖口根骨处抵消 `Bip001LClavicle` 的部分局部旋转。测试动作中，跟随 50% 和 0% 时，左袖骨姿输入最大分别抵消 18.2° 和 36.4°。其余袖链仍读回 100%，还原和停播恢复通过。该角度证据来自物理求解前的输入。最终网格的蒙皮和肩部碰撞仍需验证。

莫特斐的 Sequence 资源中，左右袖组的 `BindInfos` 均为空，每组各有一个由同侧前臂驱动的胶囊。桃祈的四条袖链共享一组，碰撞胶囊分别由两侧上臂和前臂驱动，适合后续验证同组骨链隔离及按碰撞体开关。Sequence 资源记录还需要与播放时的实际动画节点核对。3.8.0 实机已补采 `GroupApplyResult`（`0xa51030`）。其读取每个模拟骨记录的 `+0x0c` 标记及 `+0x10` 索引，为对应骨架与逐骨求解参数提供入口。

桃祈的后续会话以已验证的 compact→骨架映射绑定四条袖链，对 `Piao_L_yiXiuA02` 写入阻尼 0.03、回正强度 0.42、摆角上限 71°。其他三条袖链的逐骨缓存首尾值与基线一致。单项还原使该链阻尼回到 0.2。片段 [0.25, 1.10] 秒循环命令在实机执行并观察到回绕，随后停止恢复通过。

实时预览采集网格发布回调后的组件空间姿态，核对骨数、缓冲指针和生成号。桃祈会话读到 184 根骨，连续采样随动作变化。桃祈袖组的左右上臂、左右前臂各有一个胶囊。单独关闭左上臂后，求值列表中对应数量从 1 变为 0，另外三个均保持 1。重新开启后恢复为 1。滤选只在所选组的求值期间生效，停止恢复检查通过。莫特斐在同一帧暂停对照 100% 和 0% 肩部跟随时，发布姿态的前臂位置相同，左袖根骨位移小于 0.001 厘米，末端位移约 3.37 厘米。游戏画面的袖口仍贴在手臂上，停播恢复也已确认。

3D 视口通过单独的预览订阅读取完整组件空间姿态，常规状态文件仍按原频率更新。实机测试在 1.45 秒内分别读到莉莉的 46 帧（367 骨）和卡提希娅的 41 帧（257 骨）。在同一 0.43 秒处对照原值和 1° 摆角上限，编辑器回放两份实机姿态后，莉莉左裙摆高亮区域的最大表面位移约 1.87 厘米，卡提希娅左发束约 2.14 厘米。关闭视口订阅后姿态文件停止更新，两人的停播和恢复检查均通过。

3.8.0 原生重力由 `GroupSimulate` 读取 `node+0x1e0` 的三个浮点分量。原生求解器使用模型变换的共轭旋转和逆缩放，将世界向量转换到模型空间。验证 `GroupSimulate`、调用方与共轭系数后，Poser 仅在目标组求值期间替换向量并逐字节核对原值恢复。莉莉 `Kawaii_alpha_S08` 在动作 41.27 秒同姿势暂停对照时，原值 `[0,0,0]`、`[0,0,-250]`、`[0,0,-750]` 的左袖末端相对挂点高度分别约 +0.42、−0.39、−0.87 厘米。其余组的请求值未变化，196 次自定义求值均核对了恢复，停播恢复通过。

3.8.0 镜头管理器的当前和上一帧 POV 读取入口分别访问 `0x2f10`、`0x39e0`。引擎的缓存写入函数也确认两份缓存基址为 `0x2f00`、`0x39d0`。会话状态中的 `camera_applied_frames` 记录镜头回调应用帧数。

## 更新后的工作流程

1. 先进行只读发现，保留候选和分析证据。
2. 检查对象布局、函数签名、线程和动画阶段；确认变化后更新统一配置或适配器。
3. 按语义函数更新字节证据，重新生成并构建。
4. 运行离线回归，再单独进行获授权的游戏内画面验收。

把 `FTransform` 大小或某个 offset 改成新值，不会自动改变算法的封送和执行阶段。表情的游戏封装 API 已进行编译可行性检查，本次保留原有表情调用时序。未反射的 AnimProxy/pose/Kawaii 内部布局仍需要分析；当前没有宣称这些字段可以任意跨版本自动求解。

## 验证

```powershell
./tools/tests/game_compat_generation_checks.ps1
./tools/tests/run_native_tests.bat game_compat_resolution native_function_witness game_object_anchors
./tools/run_offline_checks.ps1
./tools/build_owned_mmd.ps1
```

这些合成测试和编译不启动或注入游戏。`run_offline_checks.ps1` 可通过 `-DotNetExecutable` 指定有 SDK 的 dotnet 路径。便携运行时部署三个必需文件及其 manifest，兼容来源随 manifest 记录。
